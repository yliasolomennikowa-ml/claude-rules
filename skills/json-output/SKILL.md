# JSON в чате

Когда она просит показать JSON или ответ сервера, ей нужен настоящий контракт для сверки с ожиданиями QA и с тем, что видит фронтенд, а не пересказ.

- Отдавай ответ сервера в том виде, в каком он приходит: те же ключи, те же значения, включая идентификаторы и полные числовые поля. Подними сервер или возьми записанный ответ.
- Не придумывай ключи, не пиши ключи кириллицей, не заворачивай ответ в обёртку вида «ожидание/факт» или сводку своего сочинения.
- Печатай JSON только с indent=2, каждый ключ на своей строке. Это касается чата, черновиков и отчётов.
- Плоская строка без переносов запрещена всегда: и в таблицах «было/станет», и ради компактности. Если таблица не вмещает развёрнутый JSON, замени её последовательностью блоков: заголовок пункта, затем два развёрнутых JSON-блока.
- Убирай ключи со значением null, затем рекурсивно убирай вложенные объекты и списки, которые после этого опустели. Под блоком одной строкой пиши «null-поля опущены».
- Если null сам по себе важен для разговора, оставь именно этот ключ и одной фразой скажи, почему.
- Сравнение «до/после» = два сырых JSON-блока, не таблица. Разбор словами только после блоков и отдельно от них.
- Перед отправкой проверь каждый фрагмент JSON: есть переносы строк, есть отступы, нет null-полей, ключи совпадают с ответом сервера.

Пример правильной формы (сервер вернул ещё `comment: null` и блок `meta` из одних null):

```json
{
  "id": 42,
  "status": "matched",
  "items": [
    {
      "code": "A1",
      "score": 0.93
    }
  ]
}
```
